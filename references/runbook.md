# 微信批量好友运行手册

仅在需要操作实时微信界面时读取本手册。默认环境是 macOS 微信桌面版；界面标签可能随版本变化。

## 1. 明确本轮范围

先记录以下配置，不从历史任务猜测：

- 源文件绝对路径、工作表、数据行范围
- 姓名、院系、年级、微信号、手机号对应列
- 好友申请语
- 备注模板，例如 `前缀{年级}{院系}{姓名}`
- 通过后的问候语
- 本轮模式：只读核对、发送申请、处理已有好友、通过后问候或状态复核

只读模式不需要发送授权。其余模式需要用户在当前任务中明确授权。

## 2. 读取和规范化名单

读取 XLSX/CSV 时：

1. 保留原始行号，使用 `工作表 + 行号` 作为稳定记录键。
2. 姓名、院系、年级、微信号、手机号全部按文本读取；不得把手机号转成科学计数法或丢失前导零。
3. 去除单元格首尾空白，不擅自改写姓名、微信号或院系。
4. 若微信号和手机号相同，只保留一个检索值。
5. 生成预期备注，并确认备注长度未被微信界面截断。
6. 对同一批内的重复微信号、重复手机号、重复预期备注和重复行进行检查。
7. 不把空白微信号、空白手机号、姓名相同或模糊匹配当作同一人。

标准化 JSON 形状：

```json
[
  {
    "sheet": "报名表",
    "row": 2,
    "name": "示例姓名",
    "department": "示例院系",
    "grade": "25本",
    "wechat": "example_wechat",
    "phone": "13800000000",
    "remark": "面试25本示例院系示例姓名"
  }
]
```

运行预检：

```bash
node scripts/validate_batch.mjs batch.json
```

有 `errors` 时停止；只有 `warnings` 时逐项核实后再决定是否继续。

## 3. 准备微信和辅助程序

1. 微信已登录，主窗口标题为“微信”，且不是锁定界面。
2. 执行 Codex/终端进程已有 macOS“辅助功能”权限。若没有，让用户手动开启；不要规避系统权限。
3. 告知用户操作期间不要切换焦点、移动或缩放微信窗口。即使用户误操作，辅助程序仍必须在输入前重新验证焦点。
4. 在本次任务临时目录编译：

```bash
swiftc /path/to/skill/scripts/wechat_ax_action.swift -o /task/tmp/wechat_ax_action
```

5. 用只读命令检查微信可访问性。不要用截图推断不可捕捉的微信界面。

## 4. 创建断点状态

首次运行创建状态文件，至少包含：

```json
{
  "source": {
    "path": "/absolute/source.xlsx",
    "sheet": "报名表",
    "fingerprint": "sha256-or-mtime-size"
  },
  "config": {
    "requestText": "...",
    "remarkTemplate": "...",
    "greetingText": "..."
  },
  "records": [
    {
      "row": 2,
      "name": "示例姓名",
      "friendStatus": "unknown",
      "requestStatus": "not_attempted",
      "remarkStatus": "not_attempted",
      "greetingStatus": "not_attempted",
      "lastOutcome": null,
      "updatedAt": null
    }
  ]
}
```

每处理一行，先写同目录临时文件，再原子重命名为正式状态文件。状态中尽量只存行号和操作结果；手机号、微信号继续以源表为准。

## 5. 只读好友审计

每人按以下顺序检索，命中后停止该行后续检索：

1. 预期备注
2. 微信号
3. 手机号

示例：

```bash
/task/tmp/wechat_ax_action check-friend '查询值'
```

分类规则：

- `localCount == 1`：在好友列表中。
- `localCount == 0`：该查询未命中，继续同一行的下一个查询值。
- `localCount > 1`：`ambiguous`，不得自动点击。
- 只有“联系人”或“最常使用”分区算本地好友；“搜索网络结果”不算。
- 三个查询都未命中才记为 `not_friend`。
- 聚焦/回读失败是 `search_error`，不是“非好友”。最多做一次无输入副作用的界面恢复；仍失败则停当前行。

完成后核对：结果条数等于源记录条数、行号唯一、首末行正确、没有未分类项。

## 6. 发送好友申请

发送前先完成该行的好友审计。

### 6.1 打开专用添加窗口

优先通过 Accessibility 元素打开：

```bash
/task/tmp/wechat_ax_action click-title '快捷操作'
/task/tmp/wechat_ax_action click-title '添加朋友'
```

确认出现标题为“添加朋友”的独立窗口，且包含标题为“搜索”的文本区和按钮。不要保存坐标，也不要在窗口宽度变化后沿用点击点。

### 6.2 逐人提交

优先使用微信号：

```bash
/task/tmp/wechat_ax_action process-one '微信号' '好友申请语' '预期备注'
```

只有返回 `NOT_FOUND_OR_UNAVAILABLE` 时，才对同一行手机号再调用一次。不得自动用姓名搜索。

处理输出：

- `RESULT=SENT`：微信已显示“已发送”或按钮变为“等待验证”；记为 `request_sent`。
- `RESULT=ALREADY_PENDING`：已有申请；记为 `already_pending`，不重复提交。
- `RESULT=NON_ADDABLE`：记录界面状态，停止当前行。
- `NOT_FOUND_OR_UNAVAILABLE`：微信号和手机号都失败后记为 `unresolved`。
- `RATE_LIMIT` 或退出码 70：立即停止整个批次。
- 提交结果无法确认：记为 `unconfirmed`，不得自动重发。

在点击“确定”之前，辅助程序必须验证申请语和备注输入框的回读值完全一致。每位完成后立即持久化状态。

## 7. 已有好友分支

用户明确授权“改备注并问候”后，可使用：

```bash
/task/tmp/wechat_ax_action process-existing-friend \
  '微信号或手机号' '预期备注' '问候语' '预期账号' '预期姓名'
```

该分支必须先精确验证联系人资料，再改备注。聊天标题必须等于预期备注，聊天框必须为空；已有完全相同的问候时跳过。身份验证失败时不做任何修改。

如果用户只要求核对好友，不得进入此分支。

## 8. 通过后发送问候

检查待问候记录时，优先按预期备注精确定位：

```bash
/task/tmp/wechat_ax_action main-search-and-greet '预期备注' '问候语'
```

若用户已手动打开正确聊天，可用：

```bash
/task/tmp/wechat_ax_action greet-current-chat '预期备注' '问候语'
```

发送条件须同时满足：

- 当前聊天标题等于预期备注
- 状态不是 `greeting_sent`
- 可访问的聊天记录中没有完全相同的问候
- 聊天输入框为空
- 粘贴后回读文本完全一致
- 未出现限频提示

发送后只有聊天框清空或能找到该消息气泡，才记为 `greeting_sent`。

## 9. 限频、误聚焦和用户中断

以下任一情况立即停止，不进入下一位：

- 出现“操作太频繁”“操作频繁”“过于频繁”“频率过快”或“请稍后再试”
- 输入落入聊天框、Codex 或其他应用
- 微信主窗口/添加窗口被关闭、锁定或结构变化
- 用户说“停下”“暂停”
- 当前行的目标身份不唯一

限频后只报告完成状态和停止原因；等待多久、何时恢复由用户决定。不得自行定时重启，除非用户明确要求创建监控或计划任务。

若误输入发生在聊天框但尚未发送，只清除能精确验证为本次注入的文本；不要覆盖用户原有草稿。

## 10. 恢复与结束校验

恢复前：

1. 核对源文件指纹；文件已变化时重新读取并对齐行号。
2. 读取状态，但对 `request_sent`、`already_pending` 和好友状态做当前界面复核。
3. 从第一个未完成或 `unconfirmed` 的记录开始；不要从头重复搜索已完成联系人。
4. 已问候记录既检查状态，也检查聊天中是否已有同文消息，避免状态文件丢失造成重复。

最终报告：

- 名单总数
- 已是好友数
- 新申请成功数
- 已等待验证数
- 已问候数与已存在问候数
- 未找到、身份歧义、结果未确认数
- 是否触发限频以及停止位置

报告用姓名和源表行号定位异常；不要展示完整手机号或微信号。源工作簿保持不变，除非用户单独授权写回状态。

## 11. 本次实践验证出的易错点

- 微信窗口不可截图时，Accessibility 仍可读取窗口、按钮、文本框和值。
- 主搜索结果中靠下的“搜索网络结果”不是好友；好友审计只能认本地联系人分区。
- 窗口宽度变化会让坐标点击失效；Accessibility 标识和每次聚焦回读更可靠。
- 用户查看进度会改变前台焦点；每次粘贴都必须重新核对目标控件。
- 连续搜同一个人通常意味着状态没有落盘或失败分支没有推进；失败后记录结果并进入明确的后续分支。
- 微信已经给出限频提示时继续操作会扩大失败范围；首次提示必须硬停。
