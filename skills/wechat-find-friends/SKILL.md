# 按条件检索微信好友

把自然语言条件转成可核验的候选集，按证据查人。默认只读；找到相似线索不等于确认身份。

## 先明确条件，再选检索顺序

- 区分 **必须满足的条件、排除条件、排序线索、用户希望执行的动作**。多个条件通常取交集；“或”保留并集分支，不擅自改写。
- 确认条件作用于谁、哪条消息及什么时间。例如“我发过欢迎语”要求本人发送，转发或引用中出现同文不能直接计入；“对方发图自报姓名”还要求图片属于该会话且语境是本人介绍。
- 年级、院系、加入日期等缺失线索若能显著缩小范围，尽早一次询问。同时做不依赖回答的检索。已有上下文足够时直接执行。
- “备注不像真名”通常是优先审阅线索，不是身份判定。不能因此永久排除已写中文名但可能备注错误的人。
- 字母前缀未明确大小写时，先兼顾大小写以免漏检，并保留原字符串。微信号、手机号、学号按文本处理，不丢前导零；同音名、相似字不自动合并。

需要条件表达、候选记录或恢复任务时，读 [条件与证据](references/conditions-and-evidence.md)。

## 优先做成本低、能排除更多候选的步骤

1. **发现可用来源**：优先当前账号的连接器或已配置、可刷新的本地工具；没有可用接口时用微信界面。数据库快照必须有账号、生成时间及刷新结果，旧快照只作线索。
2. **建立候选集**：先搜辨识度高的消息短语，或先查已有的明确名单/群成员，取决于哪一步能更快缩小范围。不要为每个人重复搜索同一条欢迎语。
3. **完成枚举**：微信搜索结果和聊天内容会虚拟加载。记录稳定标识或分页位置，滚动补齐；报告已收集数与界面总数。只看到首屏不能称为完整检索。结果区缺失、加载中或结构不认识时记为未知；只有可读的结果才能用于判断未命中。
4. **交叉核对**：对候选查看当前备注、本人介绍、群昵称和用户已有相关名单。联系人好友身份只由本地“联系人／最常使用”分区或当前资料页确认；聊天记录、群成员与网络结果中的命中不自动算好友。名单通过当前账号标识、学号等精确关联；姓名相同本身不足以关联两个账号。
5. **再看图片**：优先候选会话的姓名/报名截图，随后才考虑经范围限定的批量缓存 OCR。已过期不等于本机没有素材；有缓存也不等于有清晰原图。
6. **新增条件复用已有索引**：先筛已收集的消息和 OCR 结果，只读取尚未覆盖或已经变化的材料。不要因为用户补充院系而重新遍历全部聊天。

macOS 微信界面操作读 [界面检索](references/macos-ui.md)；本地缓存和图片索引读 [图片检索](references/cache-images.md)。

## 身份判断与可并行工作

- 每个条件分别记为 `pass`、`fail`、`unknown`，按原查询的“且／或／排除”组合判断；未知的反面仍是未知。图片模糊、素材缺失、未加载到的聊天不能算不符合。
- 证据要能回答两件事：**内容说了什么**，以及 **内容为什么属于这个联系人**。OCR 结果、文件修改时间、目录哈希、相似昵称都不能单独回答第二件事。
- 微信 UI 始终只有一个操作者。独立的名单检索、已有副本 OCR、证据整理可以并行；等待用户回答时继续这些工作。
- 若用文件读取时间变化辅助定位缓存，暂停所有会读同批源文件的扫描/OCR。程序自己读取文件也会改变 atime；未隔离的结果作废或降为未确认。
- 用户正在操作微信或另一个任务占用微信时，不争抢焦点；先做离线工作。普通只读搜索因失焦失败，可重新读界面后恢复一次。出现登录中断、限频或持续身份歧义时停止相关 UI 批次，保存进度。
- 用户暂停时中止批次并保存位置；恢复后重新确认账号、查询条件和来源指纹。当前搜索词与预期不符时，不沿用上一次结果。

## 补备注是单独授权的动作

用户要求把找到的好友加入朋友标签时，可使用已安装的 `wechat-contact-labels`。它按标签成员选择器批量处理，保留原有标签；单纯找人仍不授权创建标签或添加成员。

用户仅要求找人时不改备注、不发消息、不加好友。用户已在当前任务授权补备注时，不为每个人重复请求同一授权：

1. 先形成具体的 `原备注 → 新备注 → 字段依据`，把未知字段留空。
2. 保存前核对当前联系人账号和资料页；保存后回读新备注，记录时间及结果。未确认成功的保存不要盲目重试。
3. 使用用户要求的格式。例如用户要求“年级＋院系＋姓名”时，只写已知字段；不从年龄、入群时间或头像推测本硕博，也不自行添加或保留排序前缀。
4. 若使用已安装的 `wechat-batch-friend-requests`，读取其实时操作说明，只使用所需的备注入口；不要调用同时发送问候的组合命令。该技能的存在不扩大本任务授权。

## 结束与交付

- 分开报告已确认匹配、明确不符、仍待确认；写明实际覆盖范围和影响结论的缺口。
- 把修改前后、字段来源及保存结果记录到本次任务目录。完整账号、手机号和聊天正文留在必要的本地证据里，不在进度消息中展开。
- 说明“未找到可确认的匹配”与“确认不存在”的区别。停止没有新证据的重复搜索；不要为完成任务而猜名字。
- 本流程不删除微信缓存/聊天数据，不更改自动下载或保留设置，不自动重签、重启、注入微信进程或修改 SIP。缺少读取能力时使用现有可读来源，并如实说明缺口。
